The GPUProfiler class provides a lightweight, non-blocking GPU timing utility for measuring render pass or compute pass duration in milliseconds. It uses modern WebGPU timestamp queries, asynchronous buffer mapping, and a callback-based design to report GPU execution time without stalling the CPU or the rendering pipeline.

GPUProfiler (Class)

Wraps a WebGPU timestamp query set and associated resolve/readback buffers to measure the elapsed GPU time between paired begin() and end() calls. Results are delivered asynchronously via a user-provided callback to avoid blocking the main thread.

The profiler uses a guard flag (isMapping) to prevent overlapping measurement cycles — if a previous measurement's readback is still in flight, subsequent begin() and end() calls are silently ignored until the mapping completes.

Constructor

new GPUProfiler(device)

Creates a new GPU profiler, allocating the timestamp query set, resolve buffer, and readback buffer.

  • device (GPUDevice):
    The WebGPU device used for buffer and query set allocation. The device must support the 'timestamp-query' feature.

Allocated Resources

Resource Type Size Usage
Query Set GPUQuerySet 2 slots "timestamp" — Slot 0 for begin, slot 1 for end
Resolve Buffer GPUBuffer 16 bytes QUERY_RESOLVE | COPY_SRC — GPU-side destination for query resolution
Readback Buffer GPUBuffer 16 bytes COPY_DST | MAP_READ — CPU-mappable buffer for readback

Each buffer holds two 8-byte uint64 timestamp values (16 bytes total).

Public Methods

begin()

Records the starting GPU timestamp by submitting a minimal compute pass with a timestamp write at the beginning of the pass.

  • Returns: void

Behavior

  • Guard Check: If a previous measurement cycle is still in flight (isMapping === true), the method returns immediately without recording anything. This prevents overlapping timestamp writes that would corrupt the query set.
  • Creates a new command encoder.
  • Opens a compute pass with timestampWrites.beginningOfPassWriteIndex set to 0, writing the current GPU timestamp into query slot 0 as the pass begins.
  • Immediately ends the compute pass (no actual compute work is performed — the pass exists solely to capture the timestamp).
  • Submits the command buffer to the device queue.

Modern WebGPU API Usage

Uses the timestampWrites property on the compute pass descriptor, which is the current standard approach for writing timestamps at pass boundaries:

enc.beginComputePass({
    timestampWrites: {
        querySet: this.querySet,
        beginningOfPassWriteIndex: 0
    }
});

end(onUpdate)

Records the ending GPU timestamp, resolves the query set to a buffer, initiates an asynchronous readback, and invokes the provided callback with the measured GPU time in milliseconds once the data is available.

  • onUpdate ((gpuTimeMs: number) => void):
    Callback function that receives the measured GPU execution time in milliseconds. Called asynchronously when the timestamp data is available from the GPU (typically 1–3 frames later).
  • Returns: void

Behavior

  1. Guard Check: If isMapping is true, the method returns immediately to prevent overlapping readbacks.
  2. Creates a command encoder and opens a compute pass with timestampWrites.endOfPassWriteIndex set to 1, writing the current GPU timestamp into query slot 1.
  3. Ends the compute pass.
  4. Resolves the query set (indices 0 and 1) into the resolve buffer via enc.resolveQuerySet(). This copies the raw timestamp values from the query set into a GPU buffer.
  5. Copies the resolve buffer contents to the CPU-mappable readback buffer via enc.copyBufferToBuffer().
  6. Submits the command buffer to the device queue.
  7. Sets isMapping = true to block overlapping measurements.
  8. Calls readbackBuf.mapAsync(GPUMapMode.READ) to asynchronously request CPU access to the buffer contents.
  9. When the mapping promise resolves:
    • Reads the two uint64 timestamps from the mapped range using BigInt64Array.
    • Calculates the duration: durationNs = times[1] - times[0] (in nanoseconds).
    • Converts to milliseconds: durationMs = durationNs / 1_000_000.
    • Unmaps the readback buffer (readbackBuf.unmap()).
    • Resets isMapping = false, allowing a new measurement cycle to begin.
    • If durationMs > 0, invokes onUpdate(durationMs). A zero or negative duration (which can occur if timestamps are incorrectly ordered) is silently ignored.

Modern WebGPU API Usage

Uses timestampWrites.endOfPassWriteIndex to record the timestamp when the pass ends:

enc.beginComputePass({
    timestampWrites: {
        querySet: this.querySet,
        endOfPassWriteIndex: 1
    }
});

Measurement Cycle

Lifecycle of a Single Measurement

                         Frame N                Frame N+1              Frame N+2
                         ────────               ──────────             ──────────
CPU:  profiler.begin() ──► profiler.end() ──►   (waiting)   ──►  mapAsync resolves
                                                                       │
GPU:                    [timestamp 0]          [timestamp 1]           │
                                                                       ▼
                                                               onUpdate(ms) called

The begin() and end() calls must bracket the workload being measured. For example, to measure a render pass:

profiler.begin();
// Execute render pass(es) for the current frame
profiler.end((ms) => console.log(`GPU time: ${ms.toFixed(2)} ms`));

Due to the asynchronous GPU execution model, the begin() and end() timestamps capture the span across all submitted work between the two calls, including any render or compute passes submitted in between.

State Management

isMapping (Private Property)

A boolean guard that prevents overlapping measurement cycles:

  • Set to true when end() initiates the buffer mapping.
  • While true, both begin() and end() return immediately without performing any work.
  • Set back to false when the mapAsync promise resolves and the buffer is unmapped.

This mechanism ensures the query set and readback buffers are not written to while a readback is in progress, which would cause WebGPU validation errors or corrupted results.

Resource Cleanup

The GPUProfiler does not expose a dedicated destroy() method. The caller is responsible for managing the lifecycle of the allocated resources if they need to be released before the profiler is garbage collected:

// Manual cleanup (if necessary)
profiler.querySet.destroy?.(); // Query sets may not have destroy in all implementations
profiler.resolveBuf.destroy();
profiler.readbackBuf.destroy();

Typical Workflow

import { GPUProfiler } from './GPUProfiler';

// Ensure the device supports timestamp queries
if (!device.features.has('timestamp-query')) {
    throw new Error('Timestamp queries not supported');
}

// Create profiler
const profiler = new GPUProfiler(device);

// In the render loop:
function frame() {
    // Mark start of measured section
    profiler.begin();

    // Execute all rendering work for this frame
    renderPassEncoder.draw(...);
    // ... more draw calls, compute passes, etc.

    // Mark end and provide callback for result
    profiler.end((gpuTimeMs) => {
        console.log(`GPU frame time: ${gpuTimeMs.toFixed(2)} ms`);
        updatePerformanceHUD(gpuTimeMs);
    });

    // Note: If begin() returns early due to isMapping === true,
    // this frame's GPU work is not being measured. The callback
    // from the previous cycle will fire when its data is ready.
}

Limitations and Notes

  • Feature Requirement: The WebGPU device must be created with the 'timestamp-query' feature enabled. Without this, createQuerySet with type "timestamp" will throw an error.
  • Quantization: Timestamp resolution is GPU-dependent and may be quantized based on the GPU's clock frequency. Typical resolution is on the order of tens of nanoseconds.
  • Single Measurement in Flight: Only one measurement can be in progress at a time. If begin() is called while a previous end() is still awaiting readback, it is silently ignored. This means not every frame will be measured — measurements skip frames when the GPU pipeline is deep.
  • Wraparound: The uint64 timestamp counter may wrap around after approximately 580 years at typical GPU clock rates, making wraparound a non-issue in practice.
  • Negative Durations: If times[1] - times[0] is zero or negative (which should not occur with correct begin()/end() ordering), the callback is not invoked.
  • Pass Type: The implementation uses beginComputePass rather than beginRenderPass for timestamp insertion, as it is the most lightweight pass type that supports timestamp writes. The compute pass does not execute any actual work — it exists solely as a carrier for the timestamp query.
