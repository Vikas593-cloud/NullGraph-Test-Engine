The PerformanceWidget class provides a draggable, fixed-position on-screen display for real-time performance metrics in NullGraph. It renders FPS (frames per second), CPU frame time, and GPU frame time as both numerical readouts and a scrolling line graph — all injected directly into the DOM with self-contained CSS and touch/mouse drag support.

PerformanceWidget (Class)

A self-contained HTML/CSS/Canvas overlay that displays frame timing metrics. It self-injects its styles and markup into the document, maintains a rolling 60-frame history for CPU and GPU times, draws a live line graph on an internal canvas, and supports repositioning via mouse or touch drag.

Constructor

new PerformanceWidget()

Creates the performance widget, injecting all required CSS and HTML into the document and initializing the metric displays, graph canvas, and drag behavior.

Behavior

  1. CSS Injection: Calls injectCSS() to add a <style> block with ID ng-perf-style to the document <head>. This is idempotent — if the style block already exists, it is not duplicated.
  2. HTML Injection: Creates a <div> with ID ng-perf-widget containing:
    • A metrics grid with three individual recessed boxes: NET FPS, CPU, and GPU.
    • A <canvas> element (200×60 CSS pixels) for the scrolling history graph.
  3. Element References: Caches references to the canvas, its 2D rendering context, and the three metric <span> elements.
  4. Drag Initialization: Calls makeDraggable() to enable mouse and touch-based repositioning of the widget.

Initial State

  • FPS readout initially displays --- (until the first full second of frames is calculated).
  • CPU and GPU readouts display 0.0ms.
  • Graph history buffers are initialized with 60 zeros.
  • Widget is positioned at top: 20px; right: 20px by default.

Public Methods

tick()

Updates the FPS counter. Should be called synchronously once per animation frame to accurately track display refresh rate.

  • Returns: void

Behavior

  • Increments an internal frame counter each call.
  • Once per second (when performance.now() - lastUpdate ≥ 1000):
    • Calculates the true FPS: (frameCount × 1000) / elapsed.
    • Updates the #ng-fps element text with the true, uncapped FPS value.
    • Resets the frame counter and advances lastUpdate by exactly 1000ms (not to current time) to maintain a regular 1-second cadence regardless of frame timing irregularities.

Uncapped Display Rationale

The FPS calculation is intentionally uncapped. This ensures the widget accurately reflects true rendering output on modern high-refresh-rate monitors (e.g., 144Hz, 240Hz, 360Hz) and allows developers to measure maximum raw performance during uncapped benchmark tests.

updateMetrics(cpuMs, gpuMs)

Updates the CPU and GPU millisecond readouts and appends the values to the scrolling history graph.

  • cpuMs (number):
    CPU frame time in milliseconds. Typically measured via performance.now() delta between frames or from a JavaScript profiler.
  • gpuMs (number):
    GPU frame time in milliseconds. Typically received asynchronously from a GPUProfiler callback. A value of 0 indicates that GPU timing data is not yet available or not supported.
  • Returns: void

Behavior

  1. Appends cpuMs to the CPU history array and shifts the oldest value off the front (maintaining a fixed length of 60 samples).
  2. Appends gpuMs to the GPU history array with the same push/shift rolling window.
  3. Updates the CPU readout text with the formatted value (1 decimal place).
  4. Updates the GPU readout:
    • If gpuMs === 0: displays "N/A" in dim gray (#555) to indicate no GPU timing data is available.
    • If gpuMs > 0: displays the formatted value in cyan (#00ffcc).
  5. Calls drawGraph() to re-render the canvas with the updated history data.

Internal Methods

drawGraph() (Private)

Renders the scrolling performance history graph onto the internal canvas.

  • Returns: void

Behavior

Canvas Resolution Handling

The canvas uses device pixel ratio (DPR) scaling for crisp rendering on high-DPI displays:

  • Checks if the canvas backing store dimensions match cssWidth × dpr and cssHeight × dpr.
  • If mismatched (e.g., after DPR change or initialization), resizes the backing store and resets the drawing transform.

Drawing Sequence

  1. Clears the canvas with clearRect (transparent background — the CSS background: rgba(0,0,0,0.5) on the canvas element provides the dark backdrop).
  2. Scales the context by dpr so all subsequent drawing uses CSS pixel coordinates.
  3. Draws a horizontal reference line at the 16.6ms mark (representing 60 FPS target):
    • The line position is calculated as height - (16.6 / 32) × height.
    • Drawn in translucent white (rgba(255,255,255,0.15)).
  4. Draws the CPU history path in yellow (#ffcc00) using drawPath().
  5. Draws the GPU history path in cyan (#00ffcc) using drawPath().

Vertical Scale

Both paths use a fixed vertical scale of 0–32ms, where the bottom of the graph represents 0ms and the top represents 32ms. Values exceeding 32ms are clamped to the top of the graph. The horizontal step between samples is calculated as canvasWidth / (HISTORY_SIZE - 1).

drawPath(data, color, step, height) (Private)

Draws a single polyline path from a history array onto the canvas.

  • data (number[]):
    Array of millisecond values (length HISTORY_SIZE, currently 60).
  • color (string):
    CSS color string for the stroke (e.g., '#ffcc00').
  • step (number):
    Horizontal pixel distance between consecutive data points.
  • height (number):
    Canvas CSS pixel height for vertical scaling.
  • Returns: void

Behavior

  • Begins a new path and sets the stroke style and line width (1.5px).
  • Iterates over each millisecond value:
    • X: index × step — evenly spaced across the canvas width.
    • Y: height - (min(ms, 32) / 32) × height — inverted so lower values appear higher on the graph, clamped to 32ms maximum.
  • Uses moveTo for the first point and lineTo for subsequent points, forming a connected polyline.
  • Strokes the path.

makeDraggable(el) (Private)

Enables mouse and touch drag functionality on the widget element, allowing the user to reposition it anywhere on the screen.

  • el (HTMLElement):
    The DOM element to make draggable (the widget container).
  • Returns: void

Behavior

Event Handling

Event Listener Target Action
mousedown Widget element Captures initial cursor position and widget position. Disables text selection via user-select: none. Switches widget from right-based positioning to left-based positioning for consistent drag math.
mousemove Document Calculates the delta from the initial cursor position and updates the widget's left and top CSS properties.
mouseup Document Ends dragging. Restores text selection.
touchstart Widget element Same as mousedown but uses touches[0] for coordinates. Registered with { passive: false } to allow preventDefault() during drag.
touchmove Document Same as mousemove but uses touches[0]. Calls preventDefault() to suppress page scrolling during drag. Registered with { passive: false }.
touchend Document Same as mouseup.

Positioning Behavior

  • On drag start, the widget's initial right CSS property is converted to a left value and right is set to auto. This ensures consistent coordinate math throughout the drag operation.
  • After the first drag, the widget remains left-positioned. A page reload (or re-injection) will reset it to the default right: 20px position.
  • There is no boundary clamping — the widget can be dragged to any screen position, including partially off-screen.

injectCSS() (Private)

Injects the widget's stylesheet into the document <head> if it has not already been added.

  • Returns: void

Idempotency

Uses a guard check on document.getElementById('ng-perf-style'). If a style element with that ID already exists, the method returns immediately. This prevents duplicate style injections when multiple widgets are created in a single page lifecycle.

Visual Design

  • Glassmorphism: Dark, frosted-glass effect with a subtle linear gradient background, backdrop blur (backdrop-filter: blur(12px)), and refined drop shadows to simulate a high-end dev tool overlay.
  • Drag Handle: Features a visual pill-shaped indicator at the top to communicate draggability.
  • Structured Layout: Places each metric (FPS, CPU, GPU) into isolated, dark recessed boxes (background: rgba(0, 0, 0, 0.4)) for clear readability.
  • Dual Typography: Uses a clean sans-serif font (Inter, system defaults) for labels, and strict monospace fonts (JetBrains Mono, Fira Code, etc.) for values to prevent horizontal text jittering as numbers rapidly change.
  • Z-Index: z-index: 9999 ensures visibility above most page content.
  • Interactivity: cursor: grab with :active state changing to grabbing. The internal canvas has pointer-events: none so drag events pass through to the container.

Typical Workflow

import { PerformanceWidget } from './PerformanceWidget';
import { GPUProfiler } from './GPUProfiler';

// Create the widget (self-injects into DOM)
const perfWidget = new PerformanceWidget();

// Create GPU profiler for GPU timing
const gpuProfiler = new GPUProfiler(device);

// Track CPU time manually
let lastCpuTime = performance.now();

// In the render loop:
function frame() {
    // 1. Update FPS (every frame, synchronous)
    perfWidget.tick();

    // 2. Measure CPU time
    const now = performance.now();
    const cpuMs = now - lastCpuTime;
    lastCpuTime = now;

    // 3. Begin GPU timing scope
    gpuProfiler.begin();

    // ... execute all render/compute passes ...

    // 4. End GPU timing and update widget when data arrives
    gpuProfiler.end((gpuMs) => {
        perfWidget.updateMetrics(cpuMs, gpuMs);
    });

    // Note: updateMetrics can also be called synchronously with just CPU data
    // if GPU data is not yet available:
    // perfWidget.updateMetrics(cpuMs, 0);
}
