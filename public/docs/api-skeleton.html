Here is the API reference for the `SkeletonManager` class, formatted in the requested style. ---

The SkeletonManager class manages the GPU-side uniform buffer for skeletal animation data in NullGraph. It allocates a fixed-size buffer for bone matrices, provides initialization to identity (bind pose), and offers a streamlined update path from an Animator instance — bridging the gap between CPU animation evaluation and GPU shader consumption.

SkeletonManager (Class)

Wraps a WebGPU uniform buffer that holds an array of 4×4 bone transformation matrices for hardware skinning. The buffer is sized to accommodate a configurable maximum number of bones and is designed for per-frame updates from an external animation system.

Constructor

new SkeletonManager(device, maxBones?)

Creates a new skeleton manager, allocating a GPU uniform buffer for bone matrices and initializing it to the identity bind pose.

  • device (GPUDevice):
    The WebGPU device used for buffer allocation and data upload.
  • maxBones (number):
    Optional. The maximum number of bones (4×4 matrices) to allocate space for.
    Defaults to 70, matching the WGSL shader array size array<mat4x4<f32>, 70> defined in PBRChunks.SkinningBindings.

GPU Buffer Allocation

The internal bone buffer is created with the following properties:

  • Size: maxBones × 16 × 4 bytes (16 floats per 4×4 matrix, 4 bytes per f32)
  • Usage: GPUBufferUsage.UNIFORM | GPUBufferUsage.COPY_DST
  • Allocated once at construction time and reused across all frames

Public Properties

  • boneBuffer: GPUBuffer
    The GPU uniform buffer containing the flattened array of bone matrices.
    This buffer is intended to be bound to the shader's skeleton bind group (group 2, binding 0 in the standard PBR pipeline).
  • maxBones: number
    The maximum number of bones this skeleton supports. Determined at construction time.

Buffer Initialization

resetToBindPose(device)

Resets all bone matrices in the GPU buffer to identity, representing the neutral bind pose.

  • device (GPUDevice):
    The WebGPU device used for the buffer write operation.
  • Returns: void

Behavior

  • Constructs a Float32Array of length maxBones × 16.
  • Sets each 4×4 matrix to identity by writing 1.0 to the diagonal elements (indices 0, 5, 10, and 15 within each 16-float block).
  • Uploads the identity array to the GPU buffer via device.queue.writeBuffer.

Use Cases

  • Initialization immediately after construction.
  • Resetting a character to bind pose when no animation is playing.
  • Switching between animated and static rendering modes.

Identity Matrix Layout

Each 16-float block within the buffer represents a column-major 4×4 matrix:

Float Index (local) Matrix Element Value
0 Row 0, Col 0 1
1–4 ... 0
5 Row 1, Col 1 1
6–9 ... 0
10 Row 2, Col 2 1
11–14 ... 0
15 Row 3, Col 3 1

Animation Update

updateFromAnimator(device, animator)

Uploads the current frame's skinning matrices from an Animator instance to the GPU buffer.

  • device (GPUDevice):
    The WebGPU device used for the buffer write operation.
  • animator (Animator):
    The animator instance whose current skinning matrices should be uploaded. The animator must have been created with the same skin data whose joint count does not exceed maxBones.
  • Returns: void

Behavior

  • Retrieves the current flattened skinning matrix array from the animator via animator.getSkinningMatrices().
  • Writes the entire array to the GPU buffer starting at offset 0 using device.queue.writeBuffer.

Important Note

The animator's buffer must have a length no greater than maxBones × 16. If the animator was constructed from skin data with more joints than maxBones, the writeBuffer call may write beyond the allocated buffer size, causing a WebGPU validation error. Ensure consistency between the maxBones parameter, the skin data, and the WGSL shader declaration.

Resource Cleanup

The SkeletonManager does not expose a dedicated destroy() method in the current implementation. To properly release GPU resources, the caller should manage the lifecycle of boneBuffer directly:

// When no longer needed:
skeletonManager.boneBuffer.destroy();

The GPU buffer can be destroyed manually, which will invalidate the buffer and prevent further use. This is safe to call when the skeleton manager and all bind groups referencing the buffer are no longer in use.

Bind Group Integration

The boneBuffer is designed to be bound to the shader's skeleton uniform at group 2, binding 0, as defined in PBRChunks.SkinningBindings:

@group(2) @binding(0) var<uniform> skeleton: Skeleton;

A typical bind group creation for skinned rendering would look like:

const skeletonBindGroup = device.createBindGroup({
    layout: skeletonBindGroupLayout,
    entries: [
        { binding: 0, resource: { buffer: skeletonManager.boneBuffer } }
    ]
});

Typical Workflow

import { SkeletonManager } from './SkeletonManager';
import { Animator } from './Animator';

// Create skeleton GPU buffer (matches shader's array size)
const skeletonManager = new SkeletonManager(device, 70);

// Later, after loading a skinned model:
const animator = new Animator(glbData.skin);
animator.play(glbData.animations[0]);

// In the render loop:
function frame(deltaTime: number) {
    // Animate on CPU
    animator.update(deltaTime);

    // Upload to GPU
    skeletonManager.updateFromAnimator(device, animator);

    // Bind and render using skeletonManager.boneBuffer...
}

// Reset to bind pose when no animation is needed
skeletonManager.resetToBindPose(device);
