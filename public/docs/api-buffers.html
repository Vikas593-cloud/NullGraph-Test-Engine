The BatchManager and BufferManager classes form NullGraph's GPU resource allocation and draw call preparation layer. BatchManager creates fully configured RenderBatch objects — complete with render pipelines, storage buffers, indirect draw buffers, compute culling pipelines, and bind groups — and provides utilities for attaching textures, materials, and custom bind groups. BufferManager handles low-level vertex and index buffer creation with proper WebGPU alignment.

BatchManager (Class)

Central factory and manager for RenderBatch objects. It constructs GPU pipelines, allocates storage and indirect buffers, creates bind groups, and provides methods for attaching textures, materials, and custom bind groups to batches. It also manages batch lifecycle — creation, geometry assignment, data updates, and cleanup.

Constructor

new BatchManager(ctx)

Creates a new batch manager bound to a WebGPU context.

  • ctx (WebGPUContext):
    The WebGPU context providing the device, swap chain format, and camera uniform buffer reference.

Batch Creation

createBatch(pass, config)

Creates a fully configured RenderBatch, adds it to the specified render pass, and returns it for further configuration.

  • pass (RenderPassNode):
    The render pass to which the new batch will be added.
  • config (PipelineConfig):
    Configuration object specifying shader code, vertex layout, instance capacity, rendering topology, depth/stencil settings, and optional compute shader for indirect drawing.
  • Returns: RenderBatch
    The newly created and configured render batch.

Pipeline Creation

The method constructs a GPU render pipeline from the configuration:

  • Shader Module: Created from config.shaderCode with entry points 'vs_main' and 'fs_main'.
  • Color Targets: Supports multiple render targets (MRT). If config.targetFormats is provided (an array), each format becomes a separate color target. Otherwise, falls back to a single target using config.targetFormat or the context's swap chain format. Each target can optionally receive the same blend state from config.blend.
  • Vertex Layout: Taken from config.vertexLayouts, allowing dynamic stride and attribute configurations (e.g., 8-float static vs. 16-float skinned).
  • Primitive Topology: Defaults to 'triangle-list'; configurable via config.topology.
  • Depth/Stencil: Automatically enabled if the pass has a depth attachment or is a main screen pass. Uses 'depth24plus' format with configurable depthWriteEnabled and depthCompare.
  • Pipeline Layout: Uses 'auto' layout — WebGPU derives bind group layouts from shader reflection.

Buffer Allocation

  • Storage Buffer: Allocated with size maxInstances × strideFloats × 4 bytes. Usage includes STORAGE, COPY_DST, and COPY_SRC. This buffer holds per-instance transform data for rendering.

Indirect Draw & Compute Culling

If config.isIndirect is true and config.computeShaderCode is provided, the method additionally creates:

  • Indirect Buffer: 20 bytes (5 × 4) for the drawIndexedIndirect structure (indexCount, instanceCount, firstIndex, baseVertex, firstInstance). Usage includes INDIRECT, STORAGE, and COPY_DST.
  • Source Storage Buffer: Either a shared buffer from config.sharedSourceBuffer or a newly allocated buffer of same size as the storage buffer. This holds the full instance dataset for compute culling.
  • Compute Pipeline: Created from config.computeShaderCode with entry point 'cs_main'.
  • Compute Bind Group (group 0): Binds the camera uniform buffer (binding 0), source storage buffer (binding 1), destination storage buffer (binding 2), and indirect buffer (binding 3).

Default Bind Group

A render bind group (group 0) is always created, binding the camera uniform buffer (binding 0) and the storage buffer (binding 1).

Material Attachment

If config.material is provided, its applyToBatch() method is called, and the resulting bind group is stored in batch.customBindGroups[1] (the standard material bind group slot).

Pass Registration

The method automatically adds the new batch to the specified pass via pass.addBatch(batch).

Configuration Interface

PipelineConfig (Interface)

Property Type Description

strideFloats number Number of floats per instance in the storage buffer

material Material Optional material to attach at creation time

Batch Cleanup

clearBatch(pass, batch)

Removes a batch from its render pass and destroys its dedicated GPU buffers to free video memory.

  • pass (RenderPassNode):
    The render pass containing the batch.
  • batch (RenderBatch):
    The batch to remove and clean up.
  • Returns: void

Behavior

  • Calls pass.removeBatch(batch) if available; otherwise manually splices from the batches array.
  • Destroys batch.storageBuffer (always dedicated to this batch).
  • Destroys batch.indirectBuffer (always dedicated to this batch).
  • Does not destroy batch.sourceStorageBuffer — it may be shared across multiple batches via config.sharedSourceBuffer. The owner of the shared buffer is responsible for its lifecycle.

Geometry Assignment

setBatchGeometry(batch, vertexBuffer, indexBuffer, indexCount, format?)

Assigns vertex and index buffers to a batch for rendering.

  • batch (RenderBatch):
    The batch to configure.
  • vertexBuffer (GPUBuffer):
    The GPU vertex buffer to bind at slot 0.
  • indexBuffer (GPUBuffer):
    The GPU index buffer.
  • indexCount (number):
    The number of indices for direct indexed draws.
  • format (GPUIndexFormat):
    Optional. The index format ('uint16' or 'uint32'). Defaults to 'uint16'.
  • Returns: void

Instance Data Upload

updateBatchData(batch, rawData, instanceCount)

Uploads per-instance transform data to the batch's GPU storage buffer.

  • batch (RenderBatch):
    The batch to update.
  • rawData (Float32Array):
    Flat interleaved instance data (positions, rotations, scales, etc.).
  • instanceCount (number):
    The current number of active instances.
  • Returns: void

Behavior

  • Updates batch.currentInstanceCount.
  • Indirect Batches: If the batch uses indirect drawing and has a source storage buffer, data is written there (the compute shader will cull and copy to the render storage buffer). Otherwise, data is written directly to the storage buffer.
  • Static Batches: Data is written directly to batch.storageBuffer.
  • Uses device.queue.writeBuffer with the calculated byte size: instanceCount × stride × 4.

Texture Material Attachment

attachTextureMaterial(batch, textureView, sampler, extraEntries?, groupIndex?)

Creates and attaches a bind group containing a sampler, one or more texture views, and optional additional entries (such as uniform buffers) to a batch at the specified group index.

  • batch (RenderBatch):
    The batch to attach the bind group to.
  • textureView (GPUTextureView | GPUTextureView[]):
    A single texture view or array of texture views to bind. The first texture is bound at binding 1, the second at binding 2, etc.
  • sampler (GPUSampler):
    The sampler to bind at binding 0.
  • extraEntries (GPUBindGroupEntry[]):
    Optional. Additional bind group entries (e.g., material uniform buffers). Appended after the textures with ascending binding indices.
  • groupIndex (number):
    Optional. The bind group index to write to. Defaults to 1 (the standard material bind group slot).
  • Returns: GPUBindGroup
    The created bind group.

Binding Layout Convention

Binding Resource
0 Sampler
1 Texture view 0 (e.g., albedo)
2 Texture view 1 (e.g., normal map)
3 Texture view 2 (e.g., packed ORM)
4+ Extra entries (uniform buffers, etc.)

This matches the standard PBR shader bindings defined in PBRChunks.CommonBindings.

Custom Bind Group Attachment

attachCustomBindGroup(batch, entries, groupIndex?, target?)

Creates and attaches a fully custom bind group to a batch, with explicit control over whether it applies to the render pipeline, compute pipeline, or both.

  • batch (RenderBatch):
    The batch to attach the bind group to.
  • entries (GPUBindGroupEntry[]):
    Array of bind group entries defining the binding layout.
  • groupIndex (number):
    Optional. The bind group index. Defaults to 1.
  • target ('render' | 'compute' | 'both'):
    Optional. Which pipeline type(s) to attach to. Defaults to 'render'.
  • Returns: void

Behavior

  • Render Target: If target is 'render' or 'both', the bind group is created using the render pipeline's layout and stored in batch.customBindGroups[groupIndex].
  • Compute Target: If target is 'compute' or 'both', the bind group is created using the compute pipeline's layout and stored in batch.computeCustomBindGroups[groupIndex]. The computeCustomBindGroups object is created lazily if it doesn't exist.

Material Attachment (Generic)

attachMaterial(batch, material, groupIndex?)

Attaches a Material instance to a batch by calling its applyToBatch() method.

  • batch (RenderBatch):
    The batch to attach the material to.
  • material (Material):
    The material instance (must implement applyToBatch(batch): GPUBindGroup).
  • groupIndex (number):
    Optional. The bind group index. Defaults to 1.
  • Returns: GPUBindGroup
    The bind group returned by the material's applyToBatch method.

Integration with StandardPBRMaterial

This method is designed to work with StandardPBRMaterial and similar classes. The material's applyToBatch method internally calls attachTextureMaterial to create the bind group with textures, sampler, and a material uniform buffer.

BufferManager (Class)

A lightweight utility for creating properly aligned GPU vertex and index buffers from CPU-side typed arrays.

Constructor

new BufferManager(device)

Creates a new buffer manager bound to a GPU device.

  • device (GPUDevice):
    The WebGPU device used for buffer creation.

Vertex Buffer Creation

createVertexBuffer(data)

Creates a GPU vertex buffer and immediately uploads the provided data.

  • data (Float32Array):
    Flat interleaved vertex attribute data.
  • Returns: GPUBuffer
    A GPU buffer with VERTEX | COPY_DST usage.

Behavior

  • Creates the buffer with mappedAtCreation: true for immediate CPU upload.
  • Copies the data into the mapped range using typed array set().
  • Unmaps the buffer, making it ready for GPU use.
  • Buffer size is exactly data.byteLength — WebGPU requires 4-byte alignment, which Float32Array naturally satisfies.

Index Buffer Creation

createIndexBuffer(data)

Creates a GPU index buffer and immediately uploads the provided data.

  • data (Uint16Array | Uint32Array):
    Index data defining triangle connectivity.
  • Returns: GPUBuffer
    A GPU buffer with INDEX | COPY_DST usage.

Behavior

  • Rounds the buffer size up to the nearest multiple of 4 bytes via Math.ceil(data.byteLength / 4) * 4. This ensures 4-byte alignment required by WebGPU, which is particularly important for Uint16Array data where an odd number of indices could result in a non-aligned byte length.
  • Creates the buffer with mappedAtCreation: true.
  • Copies the data using the appropriate typed array view (Uint16Array or Uint32Array) into the mapped range.
  • Unmaps the buffer for GPU use.

Alignment Note

WebGPU requires all buffer sizes to be multiples of 4 bytes. For Uint16Array index buffers with an odd number of indices, the byte length will be 2 × oddNumber, which is not a multiple of 4. The rounding ensures compliance, and the extra padding bytes are ignored by the GPU since the index count is specified separately in draw calls.

Typical Workflow

import { WebGPUContext } from './WebGPUContext';
import { BatchManager } from './BatchManager';
import { BufferManager } from './BufferManager';
import { RenderPassNode } from './RenderPass';
import { StandardPBRMaterial } from './StandardPBRMaterial';
import { buildPBRShader } from './ShaderBuilder';

const ctx = new WebGPUContext(/* ... */);
const batchManager = new BatchManager(ctx);
const bufferManager = new BufferManager(ctx.device);

// Create a render pass
const mainPass = new RenderPassNode({
    name: 'Main',
    isMainScreenPass: true
});

// Create a static PBR shader
const shaderCode = buildPBRShader({ useSkinning: false });

// Create a batch
const batch = batchManager.createBatch(mainPass, {
    shaderCode,
    strideFloats: 14,  // 2 padding + 3 pos + 4 rot + 3 scale + 2 padding
    maxInstances: 1000,
    vertexLayouts: [{
        arrayStride: 32,  // 8 floats × 4 bytes (static mesh)
        attributes: [
            { format: 'float32x3', offset: 0,  shaderLocation: 0 },
            { format: 'float32x3', offset: 12, shaderLocation: 1 },
            { format: 'float32x2', offset: 24, shaderLocation: 2 }
        ]
    }],
    topology: 'triangle-list',
    material: myPBRMaterial  // Optional: attach a material
});

// Upload geometry
const vertices = new Float32Array(/* ... */);
const indices = new Uint16Array(/* ... */);
const vbo = bufferManager.createVertexBuffer(vertices);
const ibo = bufferManager.createIndexBuffer(indices);
batchManager.setBatchGeometry(batch, vbo, ibo, indices.length, 'uint16');

// Upload instance data
const instanceData = new Float32Array(/* 14 floats per instance × N instances */);
batchManager.updateBatchData(batch, instanceData, instanceCount);

// Clean up when done
batchManager.clearBatch(mainPass, batch);
