The MegabufferBuilder class combines multiple meshes into a single large vertex and index buffer ("Megabuffer") for efficient GPU rendering, batching, and indirect draw workflows.

MeshOffset (Interface)

Describes where a mesh resides inside the combined megabuffer.

Properties

  • indexCount: number
    Total number of indices belonging to the mesh.
    • ```
  • firstIndex: number
    Starting index offset inside the global index buffer.
  • baseVertex: number
    Starting vertex offset inside the global vertex buffer.
  • meshID: number
    Automatically assigned unique mesh identifier.
    Useful for GPU-driven rendering and compute workflows.
  • vertexCount?: number
    Optional vertex count metadata for the mesh.
    • ```

MegabufferBuilder (Class)

A utility for merging multiple independent meshes into one contiguous vertex/index buffer pair.

This approach minimizes GPU state changes and enables:

  • Batch rendering
  • Indirect drawing
  • GPU-driven rendering
  • Mesh streaming systems
  • Single-buffer scene uploads

Constructor

new MegabufferBuilder(vertexStrideFloats?)

Creates a new megabuffer builder.

  • vertexStrideFloats (number):
    Number of 32-bit floats that make up a single vertex.
    Defaults to 6.

Example

// Position + Normal
const builder = new MegabufferBuilder(6);

// Position + Normal + UV
const builder = new MegabufferBuilder(8);

Mesh Addition

addMesh(name, meshVertices, meshIndices)

Adds a mesh into the megabuffer and returns its calculated offsets.

  • name (string):
    Unique mesh identifier used for lookup.
    • ```
  • meshVertices (Float32Array | number[]):
    Flat interleaved vertex data.
  • meshIndices (Uint16Array | number[]):
    Mesh index data.
  • Returns: MeshOffset
    • ```

Behavior

  • Appends incoming vertex data into the master vertex array.
  • Appends incoming index data into the master index array.
  • Automatically calculates:
    • baseVertex
    • firstIndex
    • indexCount
    • ```
  • Assigns an auto-incrementing meshID.
  • Stores mesh offsets internally for future lookup.
    • ```

Megabuffer Finalization

build()

Builds the final combined typed arrays suitable for GPU upload.

  • Returns: 
    {
    megaVertices: Float32Array,
    megaIndices: Uint16Array | Uint32Array,
    indexFormat: GPUIndexFormat
}

Behavior

  • Converts accumulated arrays into GPU-ready typed arrays.
  • Automatically selects the correct index format based on vertex count.
  • Uses Uint32Array when vertex count exceeds WebGPU's 16-bit limit.

Index Format Selection

The builder automatically switches index formats using the following logic:

\text{Use Uint32 if TotalVertices} > 65535
  • Uint16Array → Up to 65,535 vertices
  • Uint32Array → Larger meshes

Offset Lookup

getOffset(name)

Retrieves the stored offset information for a previously added mesh.

  • name (string): Mesh identifier.
    • ```
  • Returns: MeshOffset
    • ```

Behavior

  • Looks up the mesh offset by name.
  • Throws an error if the mesh does not exist.

Error Example

Error: Mesh 'Tree_01' not found in the Megabuffer!

Internal Data Management

  • vertices: number[]
    Dynamic master vertex storage array.
    • ```
  • indices: number[]
    Dynamic master index storage array.
  • offsets: Map<string, MeshOffset>
    Maps mesh names to their calculated buffer offsets.
  • currentMeshID: number
    Internal auto-incrementing mesh identifier counter.
  • vertexStrideFloats: number
    Number of floats per vertex used for offset calculations.
    • ```

Typical Workflow

const mega = new MegabufferBuilder(8);

mega.addMesh(
    "Cube",
    cubeVertices,
    cubeIndices
);

mega.addMesh(
    "Sphere",
    sphereVertices,
    sphereIndices
);

const result = mega.build();

const cubeOffset = mega.getOffset("Cube");

Rendering Use Cases

The generated offsets are designed to work directly with indexed rendering APIs such as:

drawIndexed(
    indexCount,
    instanceCount,
    firstIndex,
    baseVertex,
    firstInstance
)

This allows many meshes to coexist inside a single GPU buffer while still rendering independently.
